# ESPEZUpdater · 通用固件升级工具 设计方案

- 版本：v1.0
- 日期：2026-10-08
- 状态：**方案定稿，待实施**（本文档仅为设计说明，不含代码改动）
- 项目定位：**独立 GitHub 项目 `ESPEZUpdater`**，一套通用工具 + JSON 配置档（profile），适配任意 ESP32 项目
- 目标读者：工具维护者、接入该工具的各 ESP32 项目方（含 AI 辅助接入，见《02_面向AI的接入与出包指南.md》）

---

## 1. 背景与目标

### 1.1 现状

仓库内已有两套各自独立的固件升级工具：

| 项目 | 工具目录 | 形态 |
|---|---|---|
| ESP 桌面时钟 | `F:\ESPDesktopClock\Tools-Working\firmware-updater` | 双固件（proxy / standalone）、模式切换、三开关、串口配网（`groups` 形态） |
| ESP Virtual Keyboard | `F:\ESPVirtualKeyboard\firmware-updater` | 单固件、WiFi 配网（扁平 `status` 形态） |

**实测结论：两套工具约 80–85% 为同一份代码。**

| 共享件 | 实测 | 说明 |
|---|---|---|
| `public\esptool-js\bundle.js` | 两处 **SHA256 完全相同**（`EF7D5A23…`） | 浏览器端烧录库 |
| `esptool.exe` | 两处 **SHA256 完全相同**（`A939E28F…`） | 命令行兜底 |
| `server.ps1` | 仅控制台文案不同 | 本地静态服务（127.0.0.1:8123） |
| `一键升级.bat` / `flash_cli.bat` | 仅标题/芯片名不同 | 启动器 / CLI 兜底 |
| `gen_manifest.ps1` / `build_package.cmd` | 结构一致、参数不同 | 构建打包 |

差异集中在：固件变体数量、可编辑字段集合、变体/条件显示逻辑、固件侧配网协议的键集合、构建参数。

### 1.2 目标

1. 抽出一份**通用核心**（本地服务 + 网页 GUI + Web Serial 烧录 + 串口配网 + 构建驱动）；
2. 把项目差异全部外置为 **JSON 配置**（UI 档 `profile.json` + 构建档 `build.json`）；
3. **项目方不改工具代码**，只按《面向AI的接入与出包指南》产出「空凭据固件包 + profile」；
4. 工具自带**中英双语可切换**；
5. 分发的固件包**强制空凭据**，且打包全过程可证明不泄露。

### 1.3 非目标（本轮不做）

- 不改动任何固件源码；
- 不做「一个工具目录自动发现多个项目固件包」的包管理器；
- 不统一两端固件的协议实现（仅要求满足**协议契约**，见第 8 章）。

## 2. 设计原则

| 编号 | 原则 | 说明 |
|---|---|---|
| P1 | **配置驱动** | UI 表单、配网字段、变体、开关全部由 `profile.json` 描述；`app.js` 不含任何项目专有字段 |
| P2 | **空凭据 fail-closed** | 任一层校验失败 → 不产出任何可分发产物（见第 9 章） |
| P3 | **不影响 Arduino IDE** | 构建只改 `build_tmp` 副本；仓库 `config.h` 保留开发者凭据 |
| P4 | **版本校验** | `profile.schema`、`pong.proto` 不匹配即拒绝，避免新版工具误刷旧固件 |
| P5 | **本地闭环** | 服务仅监听 `127.0.0.1`，配网仅经 USB 串口，不经网络 |
| P6 | **最小固件假设** | 工具同时兼容「富协议（`groups`）」与「最小协议（扁平 `status`）」两种固件 |

### 3.2 每个可分发固件包（由 `build_common.ps1` 产出）

```
firmware\
├─ <variant>\                       # 单固件项目可省略变体层
│  ├─ bootloader.bin
│  ├─ partitions.bin
│  ├─ boot_app0.bin
│  ├─ app.bin
│  ├─ manifest.json
```

## 4. `profile.json` 规格（页面与配网字段）

`profile.json` **只描述字段，绝不含任何真实凭据值**。

### 4.1 顶层字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `schema` | int | ✓ | 本文档结构版本，当前 `1` |
| `proto` | int | ✓ | 期望的固件协议版本，须与设备 `pong.proto` 一致 |
| `product` | i18n | ✓ | 产品名（双语） |
| `defaultLocale` | string | | `zh` / `en`，缺省按浏览器判定 |
| `variants` | array | | 固件变体；单固件项目可省略或仅一项 |
| `switches` | object | | 开关默认值（write/update/override/erase） |
| `groups` | array | | 分组（可选，用于分区显示与状态表映射） |
| `fields` | array | ✓ | 可编辑字段 |

### 4.2 i18n 值格式

所有面向用户的文本（`product`、`variants[].label`、`groups[].label`、`fields[].label/placeholder/help`、`options[].label`）支持两种写法：

- 字符串：`"服务器地址"`（双语回退用，任何语言都显示该值）；
- 双语对象：`{ "zh": "服务器地址", "en": "Server host" }`。

### 4.3 字段对象（`fields[]`）

| 属性 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `key` | string | ✓ | **必须与固件协议支持的键一致**（如 `srvhost`、`ssid`） |
| `label` | i18n | ✓ | 显示标签 |
| `type` | string | ✓ | `text` / `password` / `number` / `textarea` / `radio` / `select` / `checkbox` |
| `group` | string | | 所属分组 id |
| `variants` | string[] | | 仅在这些变体显示；缺省=全部 |
| `placeholder` | i18n | | 占位文本 |
| `help` | i18n | | 字段下方说明 |
| `sensitive` | bool | | 仅用于 UI 掩码 + 空凭据提示，**不携带真值** |
| `maxlength` | int | | 最大长度（如 SSID 32 / 密码 63） |
| `min` / `max` | number | | `number` 类型范围 |
| `options` | array | | `radio`/`select` 选项：`[{value,label}]` |
| `default` | string | | 默认值 |
| `showWhen` | object | | 条件显示：`{ "authmode": "apikey" }` 表示仅当该字段取指定值时显示 |

## 5. `manifest.json` 规格（保持既有兼容）

`manifest.json` 由构建驱动生成，**语言中立**（仅技术信息）。

| 字段 | 类型 | 说明 |
|---|---|---|
| `version` | string | 固件版本（来自构建档 `versionMacro`） |
| `chip` | string | 目标芯片族，如 `esp32c3` |
| `credentials` | string | 固定 `"empty"`（空凭据标记） |
| `flash` | object | `{ mode, freq, size }`，驱动 `writeFlash` 与 esptool |
| `files` | array | `[{ name, offset, size, sha256 }]` 四件套 |

```json
{
  "version": "20260914",
  "chip": "esp32c3",
  "credentials": "empty",
  "flash": { "mode": "dio", "freq": "80m", "size": "4MB" },
  "files": [
    { "name": "bootloader.bin", "offset": 0,     "size": 18688,  "sha256": "...." },
    { "name": "partitions.bin", "offset": 32768, "size": 3072,   "sha256": "...." },
    { "name": "boot_app0.bin",  "offset": 57344, "size": 8192,   "sha256": "...." },
    { "name": "app.bin",        "offset": 65536, "size": 1983213,"sha256": "...." }
  ]
}
```

前端烧录前对每个文件做 SHA256 校验，失败即拒绝；`eraseAll` 由页面「擦除」开关控制；`flashMode/freq/size` 一律取自 `manifest.flash`。

## 6. 构建档（`build.json`）与 `build_common.ps1`

### 6.1 构建档字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `product` | string | ✓ | 项目标识（用于日志/zip 名） |
| `toolName` | i18n | | 工具页标题（本项目产品名） |
| `sketchDir` | string | ✓ | 项目源码根目录（**只读**） |
| `sketchName` | string | | Sketch 名；缺省取 `sketchDir` 目录名 |
| `variants` | array | | `[{ id, copySubdir, define[], undefine[] }]`；单固件缺省一项 |
| `versionMacro` | string | ✓ | 版本宏名，如 `FIRMWARE_VERSION` / `FW_VERSION` |
| `credentialMacros` | string[] | ✓ | 需强制清空的宏（L1/L2） |
| `genericNeedles` | string[] | | 通用敏感特征（L2/L3），如 Ed25519 PKCS8 前缀、真实域名 |
| `allowValues` | string[] | | 合法存在于固件中的值（白名单，不视为泄露） |
| `internalIpRegex` | string | | 内网 IP 正则（默认 `192.168/10/172.16-31`） |
| `chip` | string | ✓ | 芯片族（manifest 用） |
| `chipExpect` | string | | 前端期望芯片正则键，如 `esp32c3` |
| `fqbn` | string | ✓ | `arduino-cli` 编译参数（**须与 IDE 菜单一致**） |
| `coreDir` | string | | esp32 core 路径（取 `boot_app0.bin`） |
| `flash` | object | ✓ | `{ mode, freq, size }` |
| `appSlot` / `appWarn` | int | | 应用槽位/告警阈值（字节） |
| `profileSource` | string | ✓ | UI 档路径（拷贝为 `firmware/<变体>/profile.json`） |

### 6.4 `build_common.ps1` 流程

```
build_common.ps1 -Profile <build.json>
  0. 解析构建档；校验必填
  1. 清理 firmware\ 与 build_tmp\
  2. 对每个 variant：
     a. 复制 sketchDir 根目录 *.ino/*.h/*.cpp/*.c 到 build_tmp\<id>\<sketchName>\（不递归）
     b. 应用 variant.define / undefine（仅改副本）
     c. empty_creds.ps1：按 credentialMacros 清空副本 config.h（L1，自带自检，失败 exit 1）
     d. arduino-cli compile --fqbn <fqbn> --output-dir firmware\<id> 副本
     e. 复制四件套：bootloader/partitions/app + coreDir 的 boot_app0.bin
     f. 删除中间产物 *.ino.*
  3. 从工作目录 config.h 提取 versionMacro 值
  4. L2 源码层：断言各副本 credentialMacros 全空 + 扫描 genericNeedles + 内网 IP（allowValues 放行）
  5. L3 产物层：对 4 个 bin 做 ASCII + UTF-16LE 字节扫描（工作目录真值 + genericNeedles + 内网 IP）
  6. 写 manifest.json + VERSION.txt；拷贝 profileSource → firmware\<id>\profile.json
  7. 体积检查（appSlot / appWarn）
  8. 缺失时下载 esptool-js bundle
  9. 打包 zip（白名单排除 build_tmp\、*.elf、*.map、sdkconfig、merged.bin）
 10. 写 verify.log
```

**要点**

- 编译通过 `build_tmp` 临时副本进行，**工作目录源码零改动**；
- `empty_creds.ps1` 与 L2 断言**独立实现**，互不复用判断逻辑（避免同源缺陷）；
- 任一层失败 `exit 1`，不产出可分发产物。

## 7. 前端架构（`public/`）

### 7.1 文件职责

| 文件 | 职责 |
|---|---|
| `index.html` | 通用外壳：标题、语言切换、变体选择容器、字段容器、开关区、操作按钮、状态/进度/日志/注意事项 |
| `i18n.js` | `zh`/`en` 两套 UI 字典；`t(key)`；语言切换与持久化 |
| `app.js` | 读 `manifest.json` + `profile.json` → 动态渲染 → 烧录 → 配网 |
| `style.css` | 样式（含语言切换、动态字段、条件显示、模态框） |

### 7.2 中英双语（i18n）

- **内置字典**（工具自身文案）：标题、按钮（连接/升级/仅配网/清除）、步骤、状态、注意事项、日志模板、错误提示。
- **语言切换**：顶栏「中文 / English」；选择记入 `localStorage`；首次按 `navigator.language` 判定（`zh*` → 中文，否则英文）。
- **profile 文本**：按第 4.2 节的 i18n 值规则取值。
- **切换行为**：重渲染表单，**保留已填值**；日志历史不回溯翻译。
- **状态表**：固件回传的技术键（如 `srvhost`）优先用 profile 的 `groups`/`fields` 映射显示，无映射则原样显示。

### 7.3 渲染流程

```
init:
  locale = localStorage.locale || (navigator.language startsWith 'zh' ? 'zh' : 'en')
  manifest = GET /firmware/[variant/]manifest.json   // 变体由 profile.variants 决定根目录
  profile  = GET /firmware/[variant/]profile.json
  if manifest.credentials !== 'empty' → 红色警示「含内置凭据，请勿公开分发」
  renderVariants(profile.variants)
  renderSwitches(profile.switches)      // visible:false 的开关隐藏
  renderFields(profile.fields, selectedVariant)   // 依 variants + showWhen 过滤
```

### 7.4 烧录流程

1. `navigator.serial.requestPort()` → `new Transport` → `new ESPLoader` → `esploader.main()`；
2. 用 `manifest.chip` 派生期望芯片并校验，不符取消；
3. 逐文件 GET → SHA256 与 `manifest.files[].sha256` 比对，失败中止；
4. `writeFlash({ fileArray, flashMode/freq/size: manifest.flash, eraseAll: 擦除开关, compress:true })`；
5. `esploader.after('hard_reset')` → 释放串口。

### 7.5 配网流程（`@` + 单行 JSON）

1. 刷完后（或「仅配网」）重开同一 `SerialPort`（115200）；
2. 发 `@ping` 握手（校验 `proto` 与 `profile.proto` 一致；`mode` 与所选变体比对）；
3. 发 `@status` 读取现状并渲染状态表；
4. 勾「写入」才下发：按 `profile.fields` 收集表单 → 组装 `@{"cmd":"creds", write, update, override, <key>:<val>…}`（**空值键不下发**）；
5. 等 `wifi_connected`（超时 45s）/ `wifi_failed` / `error` → 弹窗；
6. 发 `@status` 刷新；端口重开失败用 `navigator.serial.getPorts()` 兜底 + 用户手势重选。

### 7.6 兼容两种 `status` 形态

- **富形态**：`{ evt:"status", groups:{ key:{compile,nvs,ovr,value?} }, wifi, ip, state }` → 渲染完整状态表；
- **最小形态**：`{ evt:"status", compile, nvs, override, state, ip }` → 渲染单行摘要；
- 前端按字段存在性自适应。

## 8. 固件侧协议契约（工具不改固件，项目须满足）

> 本节是《02_面向AI的接入与出包指南》的核心依据。工具仅要求固件满足以下契约。

### 8.1 物理与格式

- 串口：USB CDC（`CDCOnBoot=cdc`）或 UART，115200；
- 单行 JSON，**`@` 前缀**；普通日志永不以 `@` 开头（与 IDE 串口监视器互不干扰）；
- 非阻塞解析，行长上限（桌面 1024B / 键盘按需），溢出丢弃。

### 8.2 命令 / 事件

| 方向 | 内容 |
|---|---|
| 工具→设备 | `@{"cmd":"ping"}` |
| 工具→设备 | `@{"cmd":"status"}` |
| 工具→设备 | `@{"cmd":"creds","write":true,"update":true,"override":false,<key>:<val>…}`（**未出现的键 = 该组不动**） |
| 工具→设备 | `@{"cmd":"creds_clear","groups":["all"]}`（可选，命令行/调试用） |
| 设备→工具 | `@{"evt":"pong","proto":1,"fw":"…","mode":"…"}`（`mode` 可选） |
| 设备→工具 | `@{"evt":"creds_saved","groups":[…],"skipped":[…],"override":false}` |
| 设备→工具 | `@{"evt":"wifi_connecting"}` / `@{"evt":"wifi_connected","ip":"…"}` / `@{"evt":"wifi_failed","status":N}` |
| 设备→工具 | `@{"evt":"status", …}`（富或最小形态，见 7.6） |
| 设备→工具 | `@{"evt":"error","msg":"…"}` |

### 8.3 凭据优先级（逐组独立判定）

| 优先级 | 条件 | 取值 |
|---|---|---|
| 1 | NVS 覆盖位=1 且 NVS 值非空 | NVS 值 |
| 2 | 编译期值非空 | 编译期值 |
| 3 | NVS 值非空 | NVS 值 |
| 4 | 全空 | 未配置（配网等待） |

- NVS 明文存储（文档注明）；
- `key` 名须与 `profile.fields[].key` **完全一致**。

### 8.4 最小实现集合（接入门槛）

一个项目至少实现：`ping→pong`、`status`、`creds`（WiFi 组）、`creds_saved`、`wifi_connected/failed`、`error`。
桌面时钟的 `groups`/多组/`authmode`/`update`/`override` 为**增强项**，可选。

## 9. 空凭据保障链（fail-closed）

**原则：任一层失败 → 不产出任何可分发产物；分层独立、互不复用判断逻辑。**

| 层 | 位置 | 检查内容 | 失败动作 |
|---|---|---|---|
| **L1 源层** | `empty_creds.ps1` | 按 `credentialMacros` 清空 `build_tmp` 副本 `config.h`；改写后自检 | `exit 1`，不编译 |
| **L2 源码层** | `build_common.ps1` | 独立解析副本断言宏全空；扫描副本源码无 `genericNeedles`、无非白名单内网 IP | `exit 1`，不写 manifest |
| **L3 产物层** | `build_common.ps1` | 对 4 个 bin 做 ASCII + UTF-16LE 字节扫描（工作目录真值反查 + `genericNeedles` + 内网 IP） | `exit 1`，删 `firmware\`，不打包 |
| **L4 发布层** | 人工 + 检查清单 | zip 由空凭据构建产出；`build_tmp\`、`*.elf/.map/sdkconfig` 不入包 | 停止发布 |

**留痕**：通过后输出 `firmware\verify.log`（扫描项、命中数=0、时间、版本），随 zip 分发。

## 11. 风险与注意事项

1. **协议形态差异**：两端固件 `status` 结构不同（`groups` vs 扁平）。工具双向兼容，但状态表呈现精细度不同。
2. **实机验证缺口**：桌面时钟串口配网（第 13 章 12–20 项）与虚拟键盘实机配网均**尚未实机验证**；通用化不改变该状态，需真机回归。
3. **profile ↔ 固件键漂移**：接入指南要求键名对齐；建议在 L2 增加「profile 字段键 ⊆ 固件支持键」的一致性检查（可选增强）。
4. **FQBN 必须与 IDE 一致**：`CDCOnBoot=cdc`（USB CDC Enabled）与 `FlashMode=dio` 错误会导致无串口或无法启动。
5. **版本校验**：`profile.schema`/`pong.proto` 不匹配必须拒绝，避免误刷。
6. **仓库体积**：`esptool.exe`（约 14MB）入库，按既有决策接受。
7. **构建环境依赖**：需本机安装 `arduino-cli` 与 esp32 core（3.3.11）；`CORE_DIR` 路径由构建档指定。
