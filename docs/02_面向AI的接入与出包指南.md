# ESPEZUpdater · 面向 AI 的接入与出包指南

- 版本：v1.0
- 日期：2026-10-08
- 适用：**ESPEZUpdater**（通用固件升级工具，独立 GitHub 项目）
- 配套：`01_设计方案_通用固件升级工具.md`
- 读者：**AI 助手或项目维护者**。目标：为一个 ESP32 项目生成「空凭据固件包 + `profile.json`」，全程**不影响该项目用 Arduino IDE 继续开发**。

> **布局变更说明（2026-10-09）**：构建能力已从工具仓剥离为独立套件 `build-kit\`，
> 由项目**内置取用**并**在项目侧**构建，产物落在项目目录（缺省 `dist\`），不再写入工具仓。
> 具体机制见 `04_构建套件与项目集成机制.md`；下述命令中的 `build_common.ps1 -Profile` 请对应改为
> `build-kit\build_common.ps1 -Build <项目 build.json> [-Bundle]`。本文其余内容（字段、契约、清单）仍适用。

---

## 0. 一句话说明

> 你只需为项目写两个 JSON（**构建档** `build.json` + **UI 档** `profile.json`），
> 然后运行 `build-kit\build_common.ps1 -Build <构建档>`；
> 套件会自动编译出**不含任何真实凭据**的固件包，并把 UI 档打进包里，产物落在项目侧。
> 用户用同一个 ESPEZUpdater 网页即可刷机 + 配网；项目源码与 IDE 开发不受任何影响。

## 1. 目标与前提

### 1.1 你会产出什么

| 产物 | 位置 | 说明 |
|---|---|---|
| 固件包目录 | `<工具>\firmware\[<变体>\]` | 四件套 + `manifest.json` + `profile.json` + `VERSION.txt` |
| 分发包 | `<工具>\固件升级工具_v<版本>.zip` | 含上述内容 + `verify.log`，可直接分发 |
| 空凭据证明 | `<工具>\firmware\verify.log` | L1/L2/L3 校验留痕 |

### 1.2 前提条件

1. 工具仓库 `ESPEZUpdater` 已就位（含 `build_common.ps1`、`empty_creds.ps1`、`public\`）；
2. 本机已安装 **`arduino-cli`** 与 **esp32 core（路径写入构建档 `coreDir`）**；
3. 项目源码目录可被 `arduino-cli compile` 编译（根目录含 `*.ino`）；
4. 项目固件**已实现串口配网协议契约**（见第 6.3 节；若未实现，参照第 6.4 节最小集合补充）。

> 本指南**不要求**改动项目的 `config.h` 默认值，也不要求关闭 IDE。

## 2. 产出物结构（工具生成）

```
firmware\
├─ <variant>\                # 单固件项目用一个默认变体（如 default）
│  ├─ bootloader.bin
│  ├─ partitions.bin
│  ├─ boot_app0.bin
│  ├─ app.bin
│  ├─ manifest.json          # 版本 / 芯片 / credentials:"empty" / flash / files[]
│  ├─ profile.json           # ← 由构建档 profileSource 拷贝
│  └─ VERSION.txt
└─ verify.log
固件升级工具_v<版本>.zip
```

## 3. 逐步操作

### 步骤 A：编写构建档 `xxx.build.json`

**用途**：告诉工具「从哪个源码目录、用什么参数、要清空哪些凭据宏、产出什么」。

字段含义见设计方案第 6.1 节。最小模板：

```json
{
  "product": "my-project",
  "toolName": { "zh": "我的项目 · 固件升级工具", "en": "My Project · Firmware Updater" },
  "sketchDir": "F:\\path\\to\\MyProject",
  "sketchName": "MyProject",
  "variants": [ { "id": "default", "copySubdir": "" } ],
  "versionMacro": "FIRMWARE_VERSION",
  "credentialMacros": [ "WIFI_SSID", "WIFI_PASSWORD", "MY_API_KEY" ],
  "genericNeedles": [],
  "allowValues": [ "127.0.0.1" ],
  "chip": "esp32c3",
  "chipExpect": "esp32c3",
  "fqbn": "esp32:esp32:esp32c3:UploadSpeed=921600,CDCOnBoot=cdc,CPUFreq=160,FlashFreq=80,FlashMode=dio,FlashSize=4M,PartitionScheme=huge_app,DebugLevel=none,EraseFlash=none",
  "coreDir": "C:\\Users\\<用户名>\\AppData\\Local\\Arduino15\\packages\\esp32\\hardware\\esp32\\3.3.11",
  "flash": { "mode": "dio", "freq": "80m", "size": "4MB" },
  "appSlot": 3145728,
  "appWarn": 2831155,
  "profileSource": "profiles\\my-project.profile.json"
}
```

**填写规则（务必遵守）**

| 要点 | 说明 |
|---|---|
| `sketchDir` | 指向**只读**的项目根目录；工具只从中复制，不会写回 |
| `fqbn` | **必须与该项目的 Arduino IDE 菜单选项一致**（尤其 `CDCOnBoot`、`FlashMode`） |
| `versionMacro` | 项目里定义版本号的宏名，工具据此命名 zip |
| `credentialMacros` | 所有**含真实凭据**的宏名，逐个列全（含多行 PEM 的宏） |
| `genericNeedles` | 与项目相关的**通用敏感特征**（如私钥前缀、真实域名）；无则留空数组 |
| `allowValues` | 固件中**合法存在**的字符串（如 `127.0.0.1`、设备自身热点名），避免误报 |
| `variants` | 多固件项目列多组；`undefine` 用于编译前注释掉某宏（如 `USE_PROXY_MODE`） |
| `profileSource` | 指向步骤 B 写的 UI 档 |

### 步骤 B：编写 UI 档 `xxx.profile.json`

**用途**：告诉网页「有哪些变体、哪些分组、哪些字段可编辑、如何双语显示」。

- 字段 `key` **必须与固件串口协议支持的键名一致**（如 `ssid`、`pass`、`srvhost`）；
- `type`：`text | password | number | textarea | radio | select | checkbox`；
- `sensitive:true` 仅用于 UI 掩码，**禁止填写真实值**；
- 面向用户的文本支持 `"字符串"` 或 `{ "zh":"…","en":"…" }`。

桌面时钟完整示例见设计方案第 4.4 节；虚拟键盘示例见第 4.5 节。最小模板：

```json
{
  "schema": 1,
  "proto": 1,
  "product": { "zh": "我的项目", "en": "My Project" },
  "defaultLocale": "zh",
  "variants": [ { "id": "default", "label": { "zh": "标准固件", "en": "Standard" } } ],
  "switches": {
    "write":    { "default": true,  "visible": true },
    "update":   { "default": true,  "visible": true },
    "override": { "default": false, "visible": true },
    "erase":    { "default": true,  "visible": true }
  },
  "groups": [ { "id": "network", "label": { "zh": "网络", "en": "Network" } } ],
  "fields": [
    { "key": "ssid", "group": "network",
      "label": { "zh": "WiFi 名称 (SSID)", "en": "WiFi SSID" },
      "type": "text", "maxlength": 32 },
    { "key": "pass", "group": "network",
      "label": { "zh": "WiFi 密码", "en": "WiFi password" },
      "type": "password", "sensitive": true, "maxlength": 63 }
  ]
}
```

### 步骤 C：运行构建

```powershell
# 在 ESPEZUpdater 目录下
powershell -NoProfile -ExecutionPolicy Bypass -File .\build_common.ps1 -Profile .\profiles\my-project.build.json
```

工具将顺序执行：清副本 → 拷贝源码 → 应用变体宏 → 清空副本凭据（L1）→ 编译 → 抽四件套 → L2 → L3 → 写 manifest/profile/VERSION → 体积检查 → 下载 bundle（缺时）→ 打包 zip → 写 verify.log。

### 步骤 D：核对空凭据

1. 打开 `firmware\verify.log`，确认 **命中数 = 0 / result: PASS**；
2. 打开 `firmware\<变体>\manifest.json`，确认 `"credentials": "empty"`；
3. 确认 zip 中**不含** `build_tmp\`、`*.elf`、`*.map`、`sdkconfig`。

### 步骤 E：本地自测

```powershell
# 双击 一键升级.bat，或：
powershell -NoProfile -ExecutionPolicy Bypass -File .\server.ps1
# 浏览器打开 http://127.0.0.1:8123
```

1. 页面应正确渲染变体/字段/开关（中文与 English 各看一遍）；
2. 未连接设备时不应报错；`manifest.credentials` 非 empty 时应显示红色警示；
3. 实机：连接设备 → 升级 → 如填了 WiFi 应自动配网并弹「完成」。

## 4. 硬性规则（AI 必须遵守）

1. **只改副本**：构建只写 `build_tmp\` 与 `firmware\`；**绝不修改 `sketchDir` 下的任何文件**，尤其 `config.h`。
2. **不提交真实凭据**：`profile.json`/构建档/示例中不得出现任何真实密码、密钥、内网 IP、域名。
3. **字段键对齐**：`profile.fields[].key` 必须命中固件配网协议支持的键，否则下发无效。
4. **FQBN 与 IDE 一致**：不得擅自改 `CDCOnBoot`/`FlashMode` 等；否则可能无串口或无法启动。
5. **凭据仅存 NVS**：真实值由使用者刷机时输入，经串口写入设备 NVS；编译期一律为空。
6. **保留 fail-closed**：不得为「让构建通过」而删除或放宽 `credentialMacros`、`genericNeedles`、L2/L3 校验。
7. **版本单调**：发布新包时更新 `versionMacro` 的值，避免与旧包混淆。

## 5. 不影响 Arduino IDE 的保证

| 保证 | 机制 |
|---|---|
| 工作区源码零改动 | 编译在 `build_tmp\<变体>\<sketchName>` 临时副本上进行 |
| 仓库 `config.h` 保留开发者凭据 | 清空只作用于**副本**；IDE 直接编译上传行为不变 |
| IDE 菜单行为一致 | 构建档 `fqbn` 显式声明与 IDE 相同的选项（含 `CDCOnBoot=cdc`、`FlashMode=dio`） |
| 分发包才空凭据 | 空凭据只影响 `firmware\` 产物与 zip，不影响工作目录 |
| IDE 串口监视器不受干扰 | 配网协议仅解析 `@` 开头行；普通 `Serial.print` 日志不触发命令 |
| 可回退 | 保留旧版固件包即可重刷回退；`flash_cli.bat` 提供命令行兜底 |

> 对开发者而言：**继续用 Arduino IDE 打开项目、改代码、编译、上传，流程完全不变。**

## 6. 契约速查

### 6.1 `profile.json` 速查（详见设计方案第 4 章）

- 顶层：`schema, proto, product, defaultLocale, variants[], switches, groups[], fields[]`
- 字段：`key, label, type, group, variants, placeholder, help, sensitive, maxlength, min, max, options, default, showWhen`
- i18n：字符串 或 `{zh,en}`

### 6.2 `manifest.json` 速查（详见第 5 章）

- `version, chip, credentials:"empty", flash{mode,freq,size}, files[{name,offset,size,sha256}]`

### 6.3 串口协议速查（详见第 8 章）

| 方向 | 内容 |
|---|---|
| 工具→设备 | `ping` / `status` / `creds`（未出现键=不动） |
| 设备→工具 | `pong{proto,fw,mode?}` / `creds_saved{groups,skipped,override}` / `wifi_connecting` / `wifi_connected{ip}` / `wifi_failed{status}` / `status{…}` / `error{msg}` |
| 优先级 | 覆盖位+NVS > 编译期 > NVS > 空 |

### 6.4 固件最小实现集合（若项目尚无配网）

1. USB 串口（`CDCOnBoot=cdc`）+ 115200；
2. 非阻塞读取，仅处理 `@` 开头行，`\n` 截止，行长上限；
3. `ping→pong{proto:1,fw}`；
4. `status`（至少 flat：`{evt,compile,nvs,override,state,ip}`）；
5. `creds`：按 key 写 NVS；支持成对 WiFi（`ssid`+`pass`）；写后回 `creds_saved`；
6. 连接结果上报 `wifi_connecting/connected/failed`；
7. 解析失败/非法参数回 `error`；
8. 提供 `ENABLE_SERIAL_PROVISION` 宏可整体关闭。

> 参考实现：桌面时钟 `ESP-Working\provision.cpp`（富协议）、虚拟键盘 `ESPVirtualKeyboard.ino`（最小协议）。

## 7. 常见错误与排查

| 现象 | 原因 | 处理 |
|---|---|---|
| L1 报「rewrite failed」 | `credentialMacros` 中某宏名在 `config.h` 中找不到或被改坏 | 核对宏名与拼写；确保每个宏确实存在 |
| L2 报「未清空: XXX」 | 该宏未被 `empty_creds.ps1` 匹配 | 检查宏定义格式（是否多行、是否带注释） |
| L2/L3 报命中敏感特征 | 源码/bin 中残留真实域名/私钥前缀/内网 IP | 从 `allowValues` 放行合法值，或彻底移除真值 |
| 编译失败 | `fqbn` 或 `coreDir` 不符 | 与 IDE/`arduino-cli` 环境对齐；核对 esp32 core 版本 |
| 页面字段不显示 | `variants`/`showWhen` 过滤 | 检查字段的 `variants` 与当前所选变体是否匹配 |
| 配网无响应（pong 超时） | 固件未实现协议，或 `CDCOnBoot` 非 `cdc` 导致无 USB 串口 | 确认固件含配网代码；`fqbn` 用 `CDCOnBoot=cdc` |
| 下发凭据无效 | `fields[].key` 与固件键名不一致 | 对齐键名（见 6.3/6.4） |
| 协议不兼容 | `profile.proto ≠ pong.proto` | 升级工具或固件，使二者一致 |
| IDE 串口监视器出现 `@…` 乱码 | 工具正在配网或设备回传事件 | 正常现象；普通日志不以 `@` 开头，不影响使用 |
