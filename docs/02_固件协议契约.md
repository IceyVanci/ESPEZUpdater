# ESPEZUpdater · 固件协议契约

- 版本：v1.1
- 日期：2026-10-09
- 配套：`docs\01_设计方案_通用固件升级工具.md`、`接入与使用说明.md`
- 说明：本文件将设计方案第 8 章独立成文，作为项目方实现/对齐串口配网协议的速查依据。**工具不改固件**，项目须满足以下契约。

> **v2 说明**：工具侧已引入通用动作模型（`profile.actions[]`，schema 2）。本契约的**命令/事件名与语义不变**；
> actions 只是对“发送哪些命令、等待哪些事件”的声明，缺省时自动合成默认动作（等同 v1 行为）。
> 详见《接入与使用说明.md》第 4 节。

## 1. 物理与格式

- 串口：USB CDC（编译选项 `CDCOnBoot=cdc`）或 UART，波特率 **115200**；
- 单行 JSON，**`@` 前缀**；普通日志永不以 `@` 开头（与 IDE 串口监视器互不干扰）；
- 非阻塞解析，行长上限（桌面 1024B / 键盘按需），溢出丢弃；
- 可选：`ENABLE_SERIAL_PROVISION` 宏（或等价开关）整体关闭配网协议。

## 2. 命令 / 事件

| 方向 | 内容 |
|---|---|
| 工具→设备 | `@{"cmd":"ping"}` |
| 工具→设备 | `@{"cmd":"status"}` |
| 工具→设备 | `@{"cmd":"creds","write":true,"update":true,"override":false,<key>:<val>…}`（**未出现的键 = 该组不动**） |
| 工具→设备 | `@{"cmd":"creds_clear","groups":["all"]}`（可选，命令行/调试用） |
| 设备→工具 | `@{"evt":"pong","proto":1,"fw":"…","mode":"…"}`（`mode` 可选） |
| 设备→工具 | `@{"evt":"creds_saved","groups":[…],"skipped":[…],"override":false}` |
| 设备→工具 | `@{"evt":"wifi_connecting"}` / `@{"evt":"wifi_connected","ip":"…"}` / `@{"evt":"wifi_failed","status":N}` |
| 设备→工具 | `@{"evt":"status", …}`（富或最小形态，见第 4 节） |
| 设备→工具 | `@{"evt":"error","msg":"…"}` |

## 3. 凭据优先级（逐组独立判定）

| 优先级 | 条件 | 取值 |
|---|---|---|
| 1 | NVS 覆盖位=1 且 NVS 值非空 | NVS 值 |
| 2 | 编译期值非空 | 编译期值 |
| 3 | NVS 值非空 | NVS 值 |
| 4 | 全空 | 未配置（配网等待） |

- NVS 明文存储（设备侧文档须注明）；
- `key` 名须与 `profile.fields[].key` **完全一致**。

## 4. 两种 `status` 形态（前端自适应）

- **富形态**：`{ evt:"status", groups:{ key:{compile,nvs,ovr,value?} }, wifi, ip, state }` → 渲染完整状态表；
- **最小形态**：`{ evt:"status", compile, nvs, override, state, ip }` → 渲染单行摘要。

## 5. 协议映射（可选扩展）

工具默认使用**方案正典**命令/事件名（第 2 节）。若项目固件使用不同命名，
可在其 `profile.json` 增加可选 `protocol` 块进行映射，无需改动固件：

```json
"protocol": {
  "ping": "ping",
  "pongEvt": "pong",
  "status": "status",
  "statusEvt": "status",
  "credsCmd": "wifi",
  "credsSavedEvt": "wifi_saved",
  "clearCmd": "wifi_clear",
  "clearAckEvt": "wifi_saved",
  "wifiConnectingEvt": "wifi_connecting",
  "wifiConnectedEvt": "wifi_connected",
  "wifiFailedEvt": "wifi_failed",
  "errorEvt": "error"
}
```

> 例：ESP 虚拟键盘固件使用 `wifi` / `wifi_saved` / `wifi_clear`，即通过该块适配。

## 6. 最小实现集合（接入门槛）

一个项目至少实现：`ping→pong`、`status`、`creds`（WiFi 组）、`creds_saved`、`wifi_connected/failed`、`error`。
富 `groups` / 多组 / `authmode` / `update` / `override` 为**增强项**，可选。
